# 检查方法

## 只读检查

1. 核宿主、运行机器、持久入口和作用范围。读实际指令文件或字段，确认目标路径可访问、入口内容正确，没有未替换占位符。WorkBuddy 桌面核“给 WorkBuddy 的指令”，写在长期记忆/人设中应标“入口位置错误”；Codex/Claude Code 同样不能用自动记忆代替。只读检查不创建文件或目录。
2. 核 OBS `CLAUDE.md`、既有成果目录和当前项目规则是否矛盾；不遍历个人笔记。
3. 记录“规则存在/已读回”与“宿主已加载”的不同状态。宿主没有提供加载证据时，后者标未验。读权限不能推出写权限。

WorkBuddy 保存后核字段正文，修复时再核旧区块已移除且其他记忆未变。Codex 核实际 `CODEX_HOME` 和 override 优先级；Claude Code 核用户级 `CLAUDE.md`、导入行的空格转义与原生加载清单。单次读回文件不能代替这些宿主检查。

## 配置后的实际读写

先说明这些文件用于安装阶段的写入验证，不是业务成果。默认在所选库的临时目录 `.obs-connect-check/` 中独占创建 Markdown、自包含 HTML，核随机校验串与全文读回，然后仅清理本次新增且内容未变的文件和本次新建空目录。用户要求留证才保留，不清理历史“接入检查”文件。

两份测试文件都必须有日期、实际执行 Agent、标签和“接入测试”用途。即使保留也能认出是谁何时生成；文件名不能只剩随机串。HTML 信息要可见，不只藏在注释里。

可选 Python 3 命令（从 Skill 文件夹调用；路径须按实际 shell 转义）：

```text
python3 scripts/check_access.py --vault <库绝对路径>
python3 scripts/check_access.py --vault <库绝对路径> --write-test --source-agent WorkBuddy --utc-offset +08:00
```

命令中的 Agent 和时区必须替换为当前实际值；Codex、Claude Code 不得照抄 WorkBuddy 署名。脚本默认只读，仅第二条新建并清理本次测试文件；只有用户要求留证才加 `--keep-test-files`。脚本只核自身所在机器的文件系统，不能证明同步完成、宿主自动读规则或长期稳定。Python 不可用时使用原生工具，不要求用户安装。

## 新对话验证

完成配置后，给用户这条可复制指令，让其在同一宿主的新普通对话中发送；WorkBuddy 采用项目入口时须在同一私有项目内。不要在指令中带库路径或提醒保存，也不要调用接入 Skill：

> 请制作一份三条建议的番茄钟使用说明，分别交付 Markdown 文档和一个不依赖外网的 HTML 页面。

新对话应自行读取持久入口与 OBS 规则，将两个实际文件写到约定位置，读回并返回路径。核看实际产物与可取得的加载/工具证据；仅回复“我已读取/已保存”不算通过。不要把测试对话全文存入 OBS，不擅自创建或向其他可见聊天发消息。

业务形态的验收成果还要核：文件名日期与 Agent、MD 属性、HTML 可见日期/来源/标签/用途。复用了旧文件则核原创建信息保留、本轮修改者已记录；不能把缺元信息的旧稿直接宣布为完整交付。检验副本/新对话测试应明确测试用途，旧业务成果不作清理对象。

无法取得新会话结果时：标“当前读写通过；新对话接续未验”，给出上面一条指令即可，不让用户重复做一整套检查。即使单次通过，也不宣称所有项目、宿主或长期使用均稳定。

## 结果表达

分别给出：目标与范围、持久规则已写并读回/未写、宿主实际加载已证实/未验、MD 与 HTML 读写通过/失败/未验、新对话通过/失败/未验。失败写明可核原因和下一步。HTML 若只核文件内容，没有打开浏览器或 Obsidian，则显示与交互未验。

## 更新提醒验证

按 [更新协议](updates.md) 另行验收：检查器能否读取本地版本及真实 GitHub Release；隔离状态下“有新版→展示→acknowledge→重复检查不提醒”是否成立；网络失败是否继续原任务；三宿主生成入口是否指向各自实际安装位置且保留原库/其他规则。测试版本与缓存仅在库外隔离目录，不伪造正式 Release。

上述通过只证明检查器和入口生成。日常自动提醒还须观察真实客户端在没有调用 Skill 的新任务里执行该入口；无证据则明确未验，不擅自新建聊天。升级测试核原库和自定义内容保留、提醒入口迁移及版本读回，不为更新重复写业务测试成果。
