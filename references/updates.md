# 更新方法

更新不阻塞保存或接入。日常任务先完成，已有工具无需新增授权时才尝试检查；没有 Python、离线或受限时跳过，不额外展开排障。

## 检查与提醒

由 Agent 调用已安装的脚本，用户不用运行命令：

```text
python3 <已安装Skill>/scripts/check_updates.py check
python3 <已安装Skill>/scripts/check_updates.py acknowledge --version <实际展示的版本>
```

固定查询本仓库最新正式 Release，默认每 24 小时至多联网一次，状态仅在库外本机缓存。`update_available` 时简短提示版本和版本页，真正展示后才 acknowledge；`up_to_date`、`local_ahead`、`already_notified` 时安静继续。失败不报“已是最新”。用户主动检查可加 `--force`；同版本已提醒记录仍保留。检查不上传库路径/笔记，不执行远端正文，不自动升级；用户要求停止时移除入口中的更新检查段，保留保存入口。

## 明确要求升级时

1. 沿用当前宿主、安装位置和已选库。固定目标 Release 下载完整 ZIP 并核校验值与解压路径；本地验收包使用用户明确提供的包。已是该版本则直接复用。
2. 内部备份，对照原发行版识别用户修改并保留，未知额外文件保留；真正冲突才问用户。正常授权后由 Agent 安装、读回完整文件集。
3. 按 [最短流程](../SKILL.md) 只补全局入口的必要差异，更新脚本指向实际安装副本。既有库内保存约定无须变化就不改，也不运行写入测试。任何一步受阻就停在具体卡点，不循环检查网络或扩成整库审计。

0.2.0 及更早的旧入口没有更新检查，需先迁移一次；只换包不等于入口已迁移。提醒依赖 Agent 运行时遵循全局入口，软件关闭时没有后台通知；不同安装分别记录，并发展示到确认之间尽力去重。实际新对话是否触发须有证据。

官方接口：[GitHub 最新 Release](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。
