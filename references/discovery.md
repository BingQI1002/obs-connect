# 先发现已登记库，再让用户选择

适用于首次启动且用户尚未指定目标库。只查当前机器可访问的库登记信息；本步骤不读取任何候选库的规则、笔记、日记或插件配置，也不改文件。用户明确限定库或机器的访问范围时先遵守该限制。

## 发现方式

优先读取本机 Obsidian 全局配置目录中的 `obsidian.json`，只提取 `vaults` 登记的路径。可选脚本 `scripts/discover_vaults.py` 默认只读，使用 Python 标准库；无 Python 时用原生文件工具按相同范围读取，不要求用户安装依赖。

| 系统 | 常用登记文件 |
|---|---|
| macOS | `~/Library/Application Support/obsidian/obsidian.json` |
| Windows | `%APPDATA%/obsidian/obsidian.json` |
| Linux | `$XDG_CONFIG_HOME/obsidian/obsidian.json`，未设环境变量时为 `~/.config/obsidian/obsidian.json` |

全局设置目录见 [Obsidian 官方说明](https://obsidian.md/help/data-storage)。`obsidian.json` 的 `vaults` 结构属于兼容性读取，并非官方承诺的稳定 API；缺文件、格式变化或权限不足时如实降级，不修改登记表“修复”。特殊安装/配置位置只在宿主已给出或用户指定后读取，不扩大为全盘搜索。

```text
python3 scripts/discover_vaults.py
python3 scripts/discover_vaults.py --registry <已知的登记文件绝对路径>
```

也可读取已有的 Obsidian 库管理界面所列名称与路径。若已有可用 CLI、应用正在运行且宿主允许，可用官方 `obsidian vaults verbose` 补充已登记路径；不为发现库启动或安装 Obsidian/CLI。CLI 的可用条件见 [官方说明](https://obsidian.md/help/cli)。

仅检查候选根目录是否存在/可访问，不列子目录，不读库内文件。按真实路径去重；重名不同路径分别保留。旧路径、离线磁盘或无权限的记录独立标记，不能自动当成可用库，也不能直接删掉登记项。

## 出选择题

说“找到 N 个已登记库”，不要声称这是用户磁盘上的全部库。区分可访问候选和需处理的旧/不可访问记录。选项展示库名和能区分它们的路径；不要只给重名库名，不根据最近打开、目录名或排序替用户选。

有原生选择工具时用它；工具放不下时分页并保留稳定编号。无工具时发简短编号列表，允许用户回复数字。例如：

> 找到 2 个已登记且可访问的库，你希望成果保存到哪个？
>
> 1. 工作笔记 — …/工作笔记
> 2. 个人资料 — …/个人资料
>
> 回复编号即可，也可以选其他文件夹。

- 只找到一个库也请用户确认选择，不自动绑定。
- 用户已明确指定目标路径时直接沿用，不强制再选；只读检查或修复现有绑定时沿用原目标，除非用户要求重新选择。
- 没找到或查不到登记信息时，先说明覆盖范围和原因，再提供“选择文件夹”或“带我找库”的选择；不说用户没有库，不先把技术路径题丢给用户。
- 用户回复后固定到当次清单中的具体路径；选择不明就核明，不从数字猜另一轮清单。确认前不读取候选库正文、不创建规则或写入测试；选中后才继续 SKILL 的规则接入与检查。

本地发现结果仅用于当次选择，不写入本仓库、共享项目或上传服务。发现脚本本身不联网、不写文件。
