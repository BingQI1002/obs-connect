# Obsidian 成果保存约定

本文件所在目录是本次接入的 Obsidian 库。它管理成果保存，不要求读取全部笔记。使用用户当次明确要求；与已有规则冲突时先核明，不默默替换。

<!-- obs-connect:rules:begin -->
## 文档与 HTML 默认保存

- 用户要求生成的文档、报告、HTML 等独立交付文件，默认保存到本库，无需每次询问是否保存；用户另指位置、只在聊天讨论或明确不保存时，按当次要求执行。
- 优先使用本库已有的成果目录；没有约定时使用 `AI成果/`，同一事项放在一起。不要重新规划整库，也不要每轮生成一份重复记录。
- 文本正文优先使用 Markdown。用户要求 Word、PDF 等格式时交付实际文件，不用改后缀冒充转换；HTML 保存实际 `.html` 文件。按阅读需要给非 Markdown 成果加简短的 Markdown 入口链接，不复制整份正文。
- 新建成果的文件名默认包含生成日期、主题和实际来源 Agent，例如 `2026-11-10_番茄钟使用说明_WorkBuddy.md`；配套 HTML 使用相同主文件名。沿用已有规范时保持其结构，并确保日期与来源可直接辨认。同名不同内容保留独立版本，不静默覆盖。
- Markdown 顶部保存 `created_at`、`source_agent`、`tags`、`purpose` 属性。生成时间使用用户时区并带偏移；只知道日期就保留日期精度，未知不补造。`source_agent` 写实际执行宿主（如 WorkBuddy、Codex、Claude Code），不能只写“AI”，也不能用模型名代替；模型可核时另列 `model`。
- 标签至少包含成果类型与 Agent，例如 `AI成果`、`Agent/WorkBuddy`；再按内容选少量主题标签，优先沿用已有标签，不堆同义标签。测试内容标 `AI接入测试` 或明确的测试用途，不能冒作正式业务成果。
- HTML 在页面可见位置同样显示生成日期、来源 Agent、标签和用途，并提供对应 `date`、`author`、`keywords` 元信息；不能只写在 HTML 注释里。其他格式在适合的封面、页尾或文档属性中保留等价信息。
- 复用、续改已有文件时保留原生成日期与创建来源，另记 `updated_at`、`updated_by`；不能把旧稿重新署名为本次 Agent。原来源无法核实时标“待核”，并写清本次修改者，不从文件修改时间猜作者。
- HTML 的图片、样式和脚本资源一并保存，优先使用相对路径。外链、需要联网的功能和尚未打开检查的交互如实说明；文件保存不代表 Obsidian 能直接预览或执行。
- 使用清楚、跨平台可用的文件名。同名不同内容保留独立版本，不静默覆盖；明确修改已有文件时，先读当前版本并在库外留恢复副本，保存前核对并发变化。新建文件采用不覆盖方式。
- 写入后读回核实实际内容与资源链接，向用户返回可点击的文件路径。云端页面、聊天预览或软件内部附件仅在实际导出落盘后才算已保存到本库。
- 草稿、AI 归纳、待核事项和已确认内容分清；默认保存成果不授权改写个人事实、长期规则或重要决定。普通闲聊不自动建档，私人日记不读取、不索引。
- 工程源码、依赖、构建缓存、完整执行日志与恢复副本留工作目录；可交付的 HTML、文档及必要资源可以入库。
- 安装阶段的写入测试不是业务成果：默认仅在临时目录创建、读回，并清理本次新增且未被修改的测试文件；用户要求留证才保留日期、Agent、标签、用途齐全的测试文件。旧“接入检查”目录和历史文件不自动删除。
- 库不可访问或无写权限时明确说明实际状态和需要的操作，不声称已保存，不擅自改为其他库。优先保留本次可取得的成果，再告知临时位置。

新建 Markdown 的属性示例（值按实际情况填写，不照抄示例日期/Agent）：

```yaml
---
created_at: "2026-11-10T12:00:00+08:00"
source_agent: WorkBuddy
tags: [AI成果, Agent/WorkBuddy, 时间管理]
purpose: 业务成果
---
```
