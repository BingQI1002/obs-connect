# OBS 接入与检查

让 Codex、Claude Code、WorkBuddy 把生成的文档、HTML 等成果保存到你自己的 Obsidian 库。

**把链接发给 Agent，由它安装、让你选库、自动配置并检查。你只负责必要的选择和授权，不用复制粘贴规则。**

## 怎么开始

把这个链接发给你正在使用的 Agent：

```text
https://github.com/BingQI1002/obs-connect
```

如果 Agent 只介绍了仓库，补一句 **“安装并启动”**。也可以第一次就发送这一行：

```text
安装并启动这个 Skill：https://github.com/BingQI1002/obs-connect
```

Agent 的[安装入口在这里](INSTALL.md)：它应先识别当前软件、安装完整 Skill，然后在**同一个对话**中开始询问，不停在“安装成功，请自己输入命令”。裸链接是否被识别为安装请求，由各 Agent 决定；它不是各软件统一的自动安装按钮。

## 接下来怎么用

Agent 会先查找电脑上 **Obsidian 已登记的库**，再让你做选择题。例如：

> 找到 2 个已登记且可访问的库，你希望成果保存到哪个？
>
> 1. 工作笔记 — …/工作笔记
> 2. 个人资料 — …/个人资料
>
> 回复编号即可，也可以选其他文件夹。

你只需选择，不必先找文件夹路径。它只读取库登记信息和根目录可访问状态，选定前不会读取候选库的规则或笔记。只有一个库也会请你确认；找不到登记信息时，再带你选择文件夹，不会直接判断你没有库。

规则创建、已有规则合并和文件读写检查，都由 Agent 完成。全局规则写入受限时，它先准备具体改动，再发起软件原生审批；你批准后，它继续原步骤。需要系统授权时，也只提示当前必要的一步。

接入完成后，日常照常提需求，例如：

> 帮我整理一份活动方案，再做一个 HTML 展示页。

Agent 应按库内约定保存实际文件并返回路径，**不用每次再调用接入 Skill，也不用重复提醒存到 OBS**。每个软件各接入一次，共用库内一份规则。

## 它会保存到哪里

- 优先沿用你已有的成果目录；没有约定时使用库内的 `AI成果/`。
- 文本成果优先保存 Markdown；需要 Word、PDF、HTML 时保存对应实际文件，HTML 所需资源一起保留。
- 新建文件名有日期、主题和来源 Agent，例如 `2026-11-10_活动方案_WorkBuddy.md`；MD 属性与 HTML 可见信息都记录生成时间、真实来源 Agent、标签和用途。模型名不能代替 Agent，复用旧稿保留原创建信息，另记修改者。
- 保留已有 `CLAUDE.md` 和目录结构；冲突条款先与你核明，不重建整库。
- 默认保存独立交付成果；普通闲聊不自动建档，工程依赖、构建缓存和完整日志留在工作目录。

## 有新版会提醒吗

从 **0.3.0** 开始，接入时会把更新检查入口一起配置好。以后照常使用 Agent，**不需要再次调用 Skill**：它按全局入口运行本地检查器，每 24 小时至多查一次本仓库最新正式版，有新版时提示版本和更新链接；同一版本实际提醒后不反复提示。用户同意升级后，Agent 备份并完成更新，保留原库和自定义规则。离线或受限时继续原任务。

这是使用时的检查，软件关闭时不会弹通知；是否在当前客户端的新对话实际触发，需要单独验证。检查状态仅留在本机缓存，不写入 OBS。检查会连接 GitHub，不上传库路径或笔记内容。

**0.2.0 及更早版本需要先迁移一次**。把仓库链接交给 Agent，并说：

```text
升级 OBS 接入，保留原库和自定义规则：https://github.com/BingQI1002/obs-connect
```

用户也可随时说“检查 OBS 接入更新”或“停止检查更新”。仅换 Skill 文件而没有迁移旧全局入口，不算自动提醒已接通。[具体检查与升级规则](references/updates.md)。

## 哪些软件能用

接入、检查与更新流程的宿主支持情况如下。

| 软件 | 从链接开始后的处理 |
|---|---|
| Codex 本机版 | 自动准备并写入生效的用户级 AGENTS 文件；工作区外写入受限时申请本次审批，批准后继续。 |
| Claude Code 本机版 | 自动准备并写入用户级 CLAUDE.md，含原生导入；必要时按软件提示批准目标目录/文件。 |
| WorkBuddy 桌面版 | 自动操作“给 WorkBuddy 的指令”并保存读回；优先用已提供的电脑操作/设置工具。macOS 另附系统界面自动化后端，首次可能需要辅助功能/自动化授权。 |

保存入口会写到各软件的**指令位置**：Codex 的用户级 `AGENTS` 文件、Claude Code 的用户级 `CLAUDE.md`、WorkBuddy 的“设置 → 个性化 → 给 WorkBuddy 的指令”。不会把它写入自动记忆或“人设设定”。

需要 Agent 能联网读仓库，并有本机文件或界面操作能力。Skill 不会自行扩大权限；申请被拒或缺少工具时，它应说清具体未完成项，不能假报成功。macOS 后端只操作 WorkBuddy 的指令字段，不编辑内部数据库或程序包；其他系统依赖宿主已有的电脑操作工具，尚没有随包的独立界面后端。没有本机通道的云端任务不能直接写本地库。

WorkBuddy 的自定义包导入方式见[官方说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。本仓库不把“市场搜索安装”当成任意 GitHub 链接安装能力。

## 怎么确认接好了

Agent 会分别核：正确全局指令入口是否写入并读回、MD/HTML 能否在库内写入读回、成果日期/来源/标签是否齐全、新对话是否自动遵循。**不会把“能写文件”当成“全局配置已完成”。**

安装阶段的技术测试默认放在库内临时目录，读回后只清理本次新增且未变化的测试文件，不再默认留下一个含随机文件名的“接入检查”成果文件夹。你要求留证时才保留，并标清日期、Agent、标签与测试用途。旧目录和历史成果不会自动删除。

HTML 保存成功不等于能在 Obsidian 内直接运行；本 Skill 不安装预览插件。新版本或新电脑上的实际结果，以接入检查为准。

## 备用下载与安装

优先把上面的链接交给 Agent。只有它无法代办安装时，才需要下面的备用方式：

- [下载最新版 Skill ZIP](https://github.com/BingQI1002/obs-connect/releases/latest/download/obs-connect.zip) · [查看版本与校验值](https://github.com/BingQI1002/obs-connect/releases/latest)
- Codex：解压后整个 `obs-connect` 文件夹放到实际支持的用户 Skill 目录，常用为 `~/.agents/skills/`；之后调用 `$obs-connect`。
- Claude Code：文件夹放入 `~/.claude/skills/`；之后调用 `/obs-connect`。
- WorkBuddy：技能 → 添加技能 → 上传技能，选择 ZIP；完成后告诉 Agent“已上传，请继续”。

日常接入不需要 API Key、额外联网服务或第三方依赖；安装和更新检查需要连接 GitHub。Python 用于本地检查与配置助手，没有 Python 时使用宿主已有工具；更新检查的替代通路须能可靠记录缓存，否则如实标未接通。

已用旧版接入且入口出现在 WorkBuddy“长期记忆”里的用户，可升级后说“修复我的 OBS 接入”；Agent 会先保存到正确指令字段，核验后仅清理对应旧区块，保留其他内容。

当前版本 **0.3.0**。配置与保存检查、更新提醒的测试范围见[版本说明](https://github.com/BingQI1002/obs-connect/releases/latest)。macOS WorkBuddy 5.9.3 已实际完成已有指令的自动修改、保存读回和原文恢复，也验证了从通用设置自动进入目标字段。三个客户端的新对话全流程、WorkBuddy 首次空白指令及 Windows/Linux 界面后端尚未全部实测，不能把文件检查当成全流程验收。发现仅覆盖已检查的库登记源，不保证磁盘上的全部库。[自动配置与官方授权依据](references/permissions.md) · [Agent 安装说明](INSTALL.md) · [Skill 正文](SKILL.md)。
